EVSE-SyncCharge: The Industrial-Grade ESP32 Charging Kernel
================================================================================
A real-time link between grid and EV, delivering millisecond-level signaling, 
OTA firmware updates, and open IoT integration.

EVSE-SyncCharge is a firmware architecture designed to transform the ESP32 into 
a fully compliant, safety-first Electric Vehicle Supply Equipment (EVSE) controller. 
Unlike basic "smart plugs," this firmware implements the full SAE J1772 / IEC 61851 
protocol stack, providing a robust foundation for dynamic load balancing and 
solar energy matching.

🚀 Core Capabilities
--------------------------------------------------------------------------------
*   **Dynamic Phase Switching (1P <-> 3P):** Automatically toggles between single-phase 
    (1.4kW - 7.4kW) and three-phase (4.1kW - 22kW) charging based on available solar 
    excess. Includes a mandatory safety interlock to protect vehicle hardware.
*   **Solar "Soft-Throttle":** Supports charging below the standard 6A limit by 
    modulating PWM duty cycle, allowing for maximum solar self-consumption even on 
    cloudy days.
*   **Enterprise Connectivity:** 
    *   **MQTT:** Native support with TLS/SSL (MQTTS) and Home Assistant Auto-Discovery.
    *   **OCPP 1.6J:** Full WebSocket (WSS) implementation for commercial backends.
    *   **Telnet Console:** Remote real-time logging and debugging interface.
*   **Zero-Preset Configuration:** No hardcoded credentials. All settings—WiFi, MQTT, 
    OCPP, and Amperage limits—are configured via a Captive Web Portal.

🛡️ Mission-Critical Safety Layer
--------------------------------------------------------------------------------
The "Goose-Cyan-Diag" kernel implements a high-integrity safety stack to protect 
the vehicle’s Onboard Charger (OBC) and the home infrastructure.

1.  **Integrated RCM Protection:** 
    Native support for Residual Current Monitors (RCM) with automated IEC-compliant 
    self-testing intervals and pre-charge safety checks.

2.  **Dual-Layer Watchdog Supervision:**
    *   **Hardware WDT:** An 8-second hardware supervisor resets the MCU in the event 
        of a network stack deadlock.
    *   **ThrottleAlive™ Protocol:** A centralized safety heartbeat that automatically 
        throttles charging to a safe minimum (6A) if external control signals 
        (MQTT/OCPP) are lost.

3.  **Synchronized Soft-Stop:** 
    Prevents contactor arcing by electronically terminating the charge via the 
    Pilot signal (State A) milliseconds before opening the mechanical relay.

4.  **OTA Interlock:** 
    During firmware updates, the system executes an immediate safety break, bypassing 
    standard debounce timers to ensure the high-voltage contactor is physically open 
    before the MCU begins flashing.

🏛️ Pro-Level Technical Deep Dive
--------------------------------------------------------------------------------
**The SAE J1772 State Machine**
The firmware uses a non-blocking state machine to decode the analog Control Pilot (CP) 
signal with millisecond precision:

| State | Pilot Voltage | Description | Firmware Action |
| :--- | :--- | :--- | :--- |
| State A | +12V | Standby / No Vehicle | PWM Off; Relay Open |
| State B | +9V ± 1 | Vehicle Detected | Start PWM; Wait for 'Ready' |
| State C | +6V ± 1 | Ready to Charge | Close Relay; Monitor Load |
| State D | +3V ± 1 | Ventilation Required | Close Relay; Log Vent State |
| State E/F | 0V / -12V | Error / Diode Fault | Emergency Stop; Lockout |

**Network Hardening**
*   **PSRAM Optimization:** Large JSON payloads (Home Assistant Discovery) are 
    offloaded to external PSRAM to preserve internal SRAM for the TLS/WiFi stack.
*   **Exponential Backoff:** Intelligent reconnection logic prevents network 
    congestion during broker outages.
*   **Smart Availability:** Implements MQTT "Last Will and Testament" (LWT) to 
    instantly mark devices as offline in Home Assistant upon power loss.

📡 Deployment & Configuration
--------------------------------------------------------------------------------

2.  **Web Portal:** Configure WiFi, MQTT, OCPP, and RCM settings.
